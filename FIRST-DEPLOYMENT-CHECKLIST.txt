FASTING TRACKER — DEPLOYMENT ACCEPTANCE CHECKLIST

Use this checklist for the current release shown in version.json.

1. Upload the CONTENTS of the release folder to the repository root in one commit.
2. Confirm index.html, version.json, manifests, localized pages, icons, LICENSE and BRANDING.md were uploaded together.
3. Do not intentionally modify sw.js for an ordinary release; the stable update protocol depends on backward compatibility.
4. Open the live version.json and confirm its version matches the release you uploaded.
5. Open the live app and confirm Settings → App version and the footer show the same version.
6. Test English, Bulgarian and Spanish interface selection.
7. Test Start Fast, Started earlier, Stop Fast, manual history entry and weight entry.
8. Confirm expected target time appears during an active fast.
9. In Settings, confirm storage-protection status, rolling recovery snapshots, external backup and import are available.
10. Export a JSON backup, verify the file was actually saved, then test Import on a disposable/test installation if practical.
11. Confirm the backup reminder does not appear on an empty installation and becomes due only after meaningful data exists.
12. If internal snapshot storage is deliberately constrained during testing, confirm the app warns that recovery protection is reduced or failed while keeping the main data save as the priority.
13. Check Settings → Updates and verify the integrity-checked update flow.
14. On a narrow phone screen, verify Settings buttons do not split words and the bottom navigation fits.
15. If changing a Home Screen icon, create an external backup first; reinstalling a PWA can remove that installation's local data and internal snapshots.

The release regression suite is in tests/test_release.py.
