FASTING TRACKER v1.0.0 — FIRST DEPLOYMENT ACCEPTANCE TEST

After GitHub Pages publishes the site, test the live URL on an iPhone before sharing it widely.

1. Open the live URL in Safari. Confirm the main app loads.
2. Add it to Home Screen and confirm the custom icon appears.
3. Launch from Home Screen. Confirm it opens standalone.
4. Start a short test fast, close the app, reopen it and confirm the timer continues.
5. Stop the test fast and confirm History and Statistics update. Delete the test entry if desired.
6. Add a weight entry, edit it and confirm the Weight chart updates.
7. Switch interface language between System, English, Bulgarian and Spanish.
8. Open Privacy and About & sources from Settings. Confirm both pages load.
9. Put the phone in Airplane Mode after one online visit. Reopen the app and the Privacy/About pages to verify offline caching.
10. Export a JSON backup to Files/iCloud, then import it and confirm data is restored.
11. Confirm the 7-day backup reminder settings/status render correctly.
12. Open version.json in Safari and confirm version is 1.0.0, protocolVersion is 1, entry is ./index.html, and the shell includes the app/public-language pages and manifests.
13. Check /robots.txt and /sitemap.xml on the live site. They should contain the final GitHub Pages URL, generated by GitHub Pages/Jekyll.
14. Share the live URL in Messages/WhatsApp and confirm the title/description/icon preview looks reasonable (preview behavior varies by service and cache).
15. Test a 72-hour (or longer) target once and confirm the health/safety confirmation appears, the Health & safety link opens, and choosing Continue still allows the target.
16. Export two backups in the same day and confirm their filenames differ by time.
17. Import a valid exported backup and confirm it restores correctly. If practical, test that a deliberately damaged backup with overlapping fasting records is rejected.
18. For update testing: later deploy v1.0.1 with a visible harmless text change, then confirm v1.0.0 detects it and Backup & Update moves to the new version without losing data. Also confirm Update without backup creates an internal recovery snapshot first.
19. If the app is intended for broad public use, prefer a dedicated custom domain/subdomain or a dedicated GitHub Pages origin. Browser storage is origin-wide, so unrelated apps hosted under the same origin should be avoided.

Do not add a .nojekyll file: this package intentionally uses GitHub Pages/Jekyll metadata to generate canonical, robots and sitemap URLs.

Additional checks:
- Test System, Light and Dark appearance on iPhone.
- Test decimal entry using both comma and dot in Bulgarian/Spanish.
- Test an entry, change the phone time zone, and verify historical times do not shift.
- Confirm the GitHub Issues support link works.
- Confirm a nonexistent URL displays the custom 404 page.

- Install once from /bg/ or /es/ (or open the app through their CTA), relaunch from Home Screen, and confirm the selected language persists.
- Visit a nested nonexistent URL and confirm the 404 page icon and “Open Fasting Tracker” link point back to the app root.
- For future ordinary releases, follow RELEASE-GUIDE.txt and leave sw.js unchanged.
20. In Safari (not the installed Home Screen app), confirm the one-time storage-separation notice appears. If you enter a test record in Safari, export it, install/open the Home Screen app, and import the backup to confirm the documented transfer path works.
21. In Settings, confirm Storage protection reports Protected / Best effort (or Unavailable if the browser does not expose the API), and that Request protection behaves sensibly. Confirm storage usage appears when available.
22. Open version.json and confirm integrityAlgorithm is SHA-256, htmlNormalization is github-pages-v1, and hashes contains one hash for every shell item.
23. Before every future release, run: python tools/build_release.py, then python tests/test_release.py. Both must pass before upload.

24. Confirm LICENSE contains the standard MIT License and BRANDING.md reserves the Fasting Tracker name/logo/icons while allowing truthful referential attribution.
25. Open About & sources and confirm the License & branding section is visible in English, Bulgarian and Spanish and that the health/privacy disclaimers remain present.
