Privacy

Fasting Tracker is designed as a local-first web app. Fasting and weight entries are kept on the device where you use the app.

What the app stores

Fasting records, deleted-fast audit records, weight entries, deleted-weight audit records, targets, preferences, achievements and recovery snapshots are stored in browser/web-app storage on your device. Primary history uses separate record-level IndexedDB stores rather than one lifetime-sized local-storage object. The app itself does not operate a backend database for those records.

Backups

When you choose Export or Backup & Update, the app creates a JSON file for you to save or share. You control where that file goes. New-format backups include a checksum and record-count manifest so the app can detect a damaged or truncated backup before restoring it. A fast or weight entry moved to Recently deleted remains in that JSON as a deleted audit record, including its original data and deletion timestamp, until you restore it or delete it permanently. Automatic rolling internal recovery snapshots remain in the same local browser storage and are not a substitute for an external backup. Snapshot payloads are compressed when the browser supports gzip compression, with a compatible JSON fallback. When enough history exists, the app retains 5 recent, 7 daily, 4 weekly and 6 monthly recovery points. If local browser storage becomes limited, the app may keep fewer internal snapshots and will show a warning with a one-tap external backup action. Exported JSON backup files are plain text and are not encrypted by Fasting Tracker, so store them somewhere you consider secure.

Import preview, merge & diagnostics

Before an external JSON backup is imported, Fasting Tracker shows its version, export time, record counts and covered date range. Replace remains available, while optional Merge deduplicates exact matches and rejects conflicting IDs, overlapping fasting records, live/deleted conflicts or incompatible active fasts. The Data & storage health panel can run an on-device integrity check and export a diagnostic JSON file containing technical information such as app/browser version, storage capability, counts, migration state and recent non-sensitive error codes. It deliberately excludes fasting start/end timestamps, weight values and history payloads.

CSV exports

Optional fasting and weight CSV files are created locally for spreadsheet use. CSV is a human-readable data export, not a complete restorable backup; JSON remains the backup format.

Network requests

The app downloads its static files and checks version.json from the same website to look for updates. It does not include advertising or analytics code and does not set tracking cookies. The hosting provider may receive ordinary web-request information such as IP address, browser/user-agent and request time under its own privacy practices.

Sharing progress

When you choose Share progress, the app prepares the selected summary locally and opens the device share sheet. The installation link is included. Weight progress is excluded by default and is shared only if you explicitly enable it. Fasting Tracker does not upload the share text itself; once you choose a destination, that destination receives what you selected under its own privacy practices.

Notifications

Device notifications are optional and require your permission. Notification preferences are stored locally and included in JSON backups, but the operating-system/browser permission itself remains controlled by the device. Fasting Tracker has no push server: it checks notification conditions while the app is running and when it is reopened, so a fully closed or suspended PWA may not deliver an alert at the exact due time. Depending on device settings, notification text may appear on the lock screen. Notification taps only reopen Fasting Tracker; notification content is not sent to a Fasting Tracker backend.

External links

Links to PubMed, NEJM, Johns Hopkins, NIH/NIA and other sources open third-party websites. Those sites have their own privacy practices.

Deleting data

Deleting one completed fast or weight entry moves it to Recently deleted: it is excluded from normal History, Statistics, charts and XP as applicable, but its audit record remains locally and in later JSON backups. You can restore it or delete that audit record permanently. Use Settings → Delete all data to clear active history, deleted-fast and deleted-weight audit history, weight data, settings and recovery snapshots. Clearing browser/site data can also remove local records. Keep an external backup if you want to preserve them.

Safari, Home Screen apps & storage protection

On iPhone and iPad, Safari and an installed Home Screen web app can use separate local storage. Records entered in Safari may therefore not automatically appear in the Home Screen app. Use Export in the copy that contains your data, then Import in the other copy to move it. The app can request persistent browser storage and shows its status in Settings; persistent storage reduces ordinary eviction risk but is not a guarantee and does not replace an external backup. Removing/uninstalling the Home Screen web app can delete that installation's local storage, including internal recovery snapshots and persistent-storage status. Before reinstalling—for example to change the icon—export an external backup and import it after reinstalling.

Public source hosting

The app is intended to be distributed as static files through GitHub Pages. GitHub's own privacy statement applies to its hosting infrastructure.

Browser storage is scoped to the website origin. If this app shares an origin with unrelated web apps, code served from those same-origin pages can potentially access the same browser storage. For a public deployment, a dedicated domain/subdomain or dedicated GitHub Pages origin is preferable.

GitHub General Privacy Statement

Поверителност

Fasting Tracker е проектиран като приложение, което пази данните локално. Записите за гладуване и тегло остават на устройството, на което използвате приложението.

Какво съхранява приложението

Записите за гладуване, одитните записи за изтрити гладувания, тегло, цели, настройки, постижения и възстановителни копия се съхраняват в локалното хранилище на браузъра/уеб приложението. Самото приложение не използва сървърна база данни за тези записи.

Архиви

При Експорт или Архивирай и обнови приложението създава JSON файл, който вие избирате къде да запазите или споделите. Гладуване, преместено в „Наскоро изтрити“, остава в този JSON като изтрит одитен запис с първоначалните времена и времето на изтриване, докато не бъде възстановено или изтрито окончателно. Автоматичните вътрешни JSON възстановителни копия остават в същото локално хранилище и не заменят външен архив. При достатъчно история приложението пази 5 последни, 7 дневни, 4 седмични и 6 месечни точки за възстановяване. Ако локалното пространство на браузъра се ограничи, приложението може да пази по-малко вътрешни копия и ще покаже предупреждение с бутон за външен архив. Експортираните JSON архиви са обикновени текстови файлове и не се криптират от Fasting Tracker, затова ги съхранявайте на място, което считате за сигурно.

CSV експорт

Незадължителните CSV файлове за гладуване и тегло се създават локално за работа с електронни таблици. CSV е четим експорт, а не пълен възстановим архив; JSON остава форматът за архивиране.

Мрежови заявки

Приложението изтегля статичните си файлове и проверява version.json от същия сайт за обновявания. Няма рекламен или аналитичен код и не задава проследяващи бисквитки. Хостинг доставчикът може да получава обичайна техническа информация за уеб заявки, например IP адрес, браузър/user-agent и време на заявката, съгласно собствените си правила.

Споделяне на напредъка

Когато изберете Сподели напредъка, приложението подготвя избраното обобщение локално и отваря системното меню за споделяне. Включва се и връзката за инсталиране. Данните за теглото са изключени по подразбиране и се споделят само ако изрично ги включите. Fasting Tracker не качва самия текст за споделяне; след като изберете получател/услуга, тя получава избраното от вас съгласно собствените си правила за поверителност.

Известия

Известията на устройството са незадължителни и изискват ваше разрешение. Настройките за известия се пазят локално и се включват в JSON архивите, но разрешението на операционната система/браузъра остава под контрола на устройството. Fasting Tracker няма push сървър: проверява условията за известия, докато приложението работи и при повторното му отваряне, затова напълно затворено или приспано PWA може да не достави известие точно в определения момент. Според настройките на устройството текстът на известията може да се вижда на заключения екран. Натискането на известие само отваря Fasting Tracker; съдържанието на известието не се изпраща към сървър на Fasting Tracker.

Външни връзки

Връзките към PubMed, NEJM, Johns Hopkins, NIH/NIA и други източници отварят сайтове на трети страни със собствени правила за поверителност.

Изтриване на данни

Изтриването на едно завършено гладуване го премества в Наскоро изтрити: то не участва в История, Статистика и XP, но одитният му запис остава локално и в следващите JSON архиви. Можете да го възстановите или да изтриете одитния запис окончателно. Използвайте Настройки → Изтрий всички данни, за да изчистите активната история, одитната история на изтритите гладувания, данните за тегло, настройките и възстановителните копия. Изчистването на данните на браузъра/сайта също може да премахне записите.

Safari, приложение на началния екран и защита на хранилището

На iPhone и iPad Safari и инсталираното уеб приложение на началния екран могат да използват отделни локални хранилища. Затова записи, въведени в Safari, може да не се появят автоматично в приложението на началния екран. Използвайте Експорт в копието, което съдържа данните, а след това Импорт в другото копие. Приложението може да поиска постоянно браузърно хранилище и показва статуса му в Настройки; това намалява риска от обичайно автоматично освобождаване на място, но не е гаранция и не заменя външен архив. Премахването/деинсталирането на приложението от началния екран може да изтрие локалното хранилище на тази инсталация, включително вътрешните възстановителни копия и статуса за постоянно хранилище. Преди преинсталиране — например за смяна на иконата — експортирайте външен архив и го импортирайте след преинсталирането.

Публичен хостинг

Приложението е предназначено за разпространение като статични файлове чрез GitHub Pages. За инфраструктурата на GitHub важи политиката за поверителност на GitHub.

Хранилището на браузъра е обвързано с произхода на уебсайта. Ако приложението споделя един и същ произход с несвързани уеб приложения, код от тези страници със същия произход потенциално може да има достъп до същото браузърно хранилище. За публично разпространение е за предпочитане отделен домейн/поддомейн или отделен GitHub Pages произход.

GitHub General Privacy Statement

Privacidad

Fasting Tracker está diseñado como una aplicación local. Los registros de ayuno y peso permanecen en el dispositivo donde utilizas la app.

Qué guarda la app

Los registros de ayuno, los registros de auditoría de ayunos eliminados, el peso, los objetivos, las preferencias, los logros y las copias de recuperación se guardan en el almacenamiento local del navegador/app web. La propia app no utiliza una base de datos de servidor para esos registros.

Copias de seguridad

Al usar Exportar o Copia y actualizar, la app crea un archivo JSON y tú decides dónde guardarlo o compartirlo. Un ayuno movido a Eliminados recientemente permanece en ese JSON como registro de auditoría eliminado, con sus tiempos originales y la marca de tiempo de eliminación, hasta que lo restaures o lo elimines permanentemente. Las copias JSON internas automáticas permanecen en el mismo almacenamiento local y no sustituyen una copia externa. Con suficiente historial, la app conserva 5 recientes, 7 diarias, 4 semanales y 6 mensuales. Si el almacenamiento local del navegador se limita, la app puede conservar menos copias internas y mostrará un aviso con una acción de copia externa de un toque. Los archivos JSON exportados son texto sin cifrar; Fasting Tracker no los cifra, así que guárdalos en un lugar que consideres seguro.

Exportaciones CSV

Los archivos CSV opcionales de ayuno y peso se crean localmente para hojas de cálculo. CSV es una exportación legible, no una copia completa restaurable; JSON sigue siendo el formato de copia de seguridad.

Solicitudes de red

La app descarga sus archivos estáticos y consulta version.json en el mismo sitio para buscar actualizaciones. No incluye publicidad ni analítica y no establece cookies de seguimiento. El proveedor de alojamiento puede recibir información técnica normal de las solicitudes web, como dirección IP, navegador/user-agent y hora de la solicitud, según sus propias prácticas.

Compartir progreso

Cuando eliges Compartir progreso, la app prepara localmente el resumen seleccionado y abre la hoja de compartir del dispositivo. También se incluye el enlace de instalación. El progreso de peso está desactivado por defecto y solo se comparte si lo activas expresamente. Fasting Tracker no sube por sí mismo el texto compartido; cuando eliges un destino, ese destino recibe lo seleccionado conforme a sus propias prácticas de privacidad.

Notificaciones

Las notificaciones del dispositivo son opcionales y requieren tu permiso. Las preferencias de notificación se guardan localmente y se incluyen en las copias JSON, pero el permiso del sistema operativo/navegador sigue bajo el control del dispositivo. Fasting Tracker no usa un servidor push: comprueba las condiciones mientras la app está en ejecución y cuando se vuelve a abrir, por lo que una PWA totalmente cerrada o suspendida puede no entregar una alerta exactamente a la hora prevista. Según los ajustes del dispositivo, el texto puede aparecer en la pantalla de bloqueo. Tocar una notificación solo vuelve a abrir Fasting Tracker; su contenido no se envía a un backend de Fasting Tracker.

Enlaces externos

Los enlaces a PubMed, NEJM, Johns Hopkins, NIH/NIA y otras fuentes abren sitios de terceros con sus propias prácticas de privacidad.

Eliminar datos

Eliminar un ayuno completado lo mueve a Eliminados recientemente: se excluye del Historial, las Estadísticas y XP, pero su registro de auditoría permanece localmente y en futuras copias JSON. Puedes restaurarlo o eliminar permanentemente ese registro de auditoría. Usa Ajustes → Eliminar todos los datos para borrar el historial activo, el historial de auditoría de ayunos eliminados, los datos de peso, los ajustes y las copias de recuperación. Borrar los datos del navegador/sitio también puede eliminar los registros.

Safari, app de pantalla de inicio y protección del almacenamiento

En iPhone y iPad, Safari y una app web instalada en la pantalla de inicio pueden usar almacenamiento local separado. Por eso, los registros introducidos en Safari pueden no aparecer automáticamente en la app de la pantalla de inicio. Usa Exportar en la copia que contiene tus datos y después Importar en la otra copia. La app puede solicitar almacenamiento persistente del navegador y muestra su estado en Ajustes; esto reduce el riesgo de eliminación automática por presión de espacio, pero no es una garantía ni sustituye una copia externa. Eliminar/desinstalar la app web de la pantalla de inicio puede borrar el almacenamiento local de esa instalación, incluidas las copias internas de recuperación y el estado de almacenamiento persistente. Antes de reinstalar —por ejemplo para cambiar el icono— exporta una copia externa e impórtala después de reinstalar.

Alojamiento público

La app está pensada para distribuirse como archivos estáticos mediante GitHub Pages. La infraestructura de alojamiento de GitHub está sujeta a su propia declaración de privacidad.

El almacenamiento del navegador está limitado por el origen del sitio web. Si esta app comparte origen con otras aplicaciones web no relacionadas, el código servido desde páginas del mismo origen podría acceder al mismo almacenamiento del navegador. Para una publicación pública es preferible usar un dominio/subdominio dedicado o un origen de GitHub Pages dedicado.
